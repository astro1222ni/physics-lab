線性搜尋與二分搜尋

在一排數字卡裡找一個數。線性搜尋從左邊一張一張看；二分搜尋要先把卡片排好，每次看正中間那一張，再丟掉一半。讓兩種方法同時跑，數一數各比了幾次；從決策樹看出二分搜尋為什麼最多只要比 \(\lfloor \log_2 n \rfloor + 1\) 次，再和一台會耍賴的電腦玩猜數字。

試試看：按「開始搜尋」，看哪一種方法先找到；再把 n 拉到 1023 比一次。

第 d 層就是第 d 次比較；亮起來的路徑是目前這次搜尋。小方塊是卡片之間的空隙，找不到的搜尋停在那裡（63 張以內才畫）。

猜數字

耍賴的電腦不先想好答案：每猜一次，它都挑讓「還可能的數」最多的那個回答。

猜中的回合會列在這裡。

背後的原理

線性搜尋：一張一張看

從最左邊那張開始，一張一張和目標比，相等就停。要找的數在第 \(i\) 張（從 \(0\) 數起）就要比 \(i + 1\) 次；陣列裡沒有的數要比完全部 \(n\) 張。如果每張卡被找的機會一樣，平均是

\[ \frac{1 + 2 + \dots + n}{n} = \frac{n + 1}{2} . \]

線性搜尋不管資料有沒有排序都能用；卡片變成兩倍，工作量也變成兩倍。

二分搜尋：每次丟掉一半

如果卡片已經由小到大排好，一次比較就能知道更多。把「目標還可能在的範圍」記成第 \(lo\) 張到第 \(hi\) 張（一開始是 \(0\) 到 \(n-1\)），看正中間那一張

\[ mid = \left\lfloor \frac{lo + hi}{2} \right\rfloor . \]

如果 \(a[mid]\) 比目標小，目標只可能在它右邊，令 \(lo = mid + 1\)；比目標大就令 \(hi = mid - 1\)；相等就找到了。等到 \(lo > hi\)，範圍變空，表示沒有這個數。每比一次，剩下的範圍最多只有原來的一半，所以比 \(k\) 次之後最多剩 \(\lfloor n / 2^{k} \rfloor\) 張。設 \(2^{k} \le n < 2^{k+1}\)，也就是 \(k = \lfloor \log_2 n \rfloor\)，再多比一次一定結束：

\[ C_{\max}(n) = \lfloor \log_2 n \rfloor + 1 . \]

這裡的「一次比較」是把目標和一張卡比，得到「小於、等於、大於」其中一個結果；線性搜尋也用同樣的算法（看一張卡算一次）。\(n = 1023\) 時，線性搜尋可能要比 1023 次，二分搜尋最多 10 次。

決策樹

把二分搜尋可能做的每一次比較畫成一個節點：第一次看的卡是樹根，「比較小」之後會看的卡是左邊的孩子，「比較大」之後是右邊的孩子，依此類推。這棵決策樹的第 \(d\) 層就是第 \(d\) 次比較，所以樹高就是最壞情況。由左到右讀節點，正好是卡片由小到大的順序——它是一棵二元搜尋樹。\(n = 2^{k} - 1\)（7、15、31、…）時每一層都排滿，叫做完美二元樹。找不到的搜尋一定停在 \(n + 1\) 個空隙之一（小方塊），比了 \(\lfloor \log_2 n \rfloor\) 或 \(\lfloor \log_2 n \rfloor + 1\) 次。

如果每張卡被找的機會一樣，平均比較次數是「平均深度加一」：設 \(I\) 是 \(n\) 個節點的深度總和（樹根深度是 0），

\[ \bar{C}_{\text{binary}} = 1 + \frac{I}{n} \approx \log_2 n - 1 \quad (n \text{ large}) . \]

為什麼一定要先排序

看到「\(a[mid]\) 比目標小」就丟掉左半邊，前提是 \(mid\) 左邊每一張都更小。打亂的資料不保證這一點，所以二分搜尋可能把藏著目標的那一半丟掉，回報「找不到」；只有它第一次看的正中間那一張保證找得到。排序本身也要花工夫，所以同一份資料要搜尋很多次時，先排序再二分搜尋才划算。

有重複的值：找第一個出現的位置

有重複的值時，一般版遇到哪一個相同的值就停在哪裡，不一定是最左邊那個。「找第一個出現的位置」這個版本在 \(a[mid]\) 等於目標時不停下來：先記住 \(mid\)，再往左邊找（\(hi = mid - 1\)），一直到範圍變空。所以它從不提早結束——每次都比 \(\lfloor \log_2 n \rfloor\) 或 \(\lfloor \log_2 n \rfloor + 1\) 次；目標不在的時候，最後的 \(lo\) 就是它應該插入的位置。

猜數字與耍賴的電腦

電腦想一個 1 到 \(N\) 的數，你猜一次，它回答「太大」「太小」或「猜中」。每次猜「還可能的數」的正中間，就是二分搜尋。猜 \(k\) 次能保證分辨的數最多只有 \(1 + 2 + \dots + 2^{k-1} = 2^{k} - 1\) 個，所以要保證猜中 \(N\) 個數裡的任何一個，至少要

\[ k_{\min} = \lceil \log_2 (N + 1) \rceil \]

次：\(N = 100\) 要 7 次，\(N = 1000\) 要 10 次。誠實的電腦有時候會讓你猜得比較快；耍賴的電腦根本不先決定答案，每次都挑讓「還可能的數」比較多的那個回答。它的回答前後一致、從不說謊，卻能逼任何猜法至少用 \(k_{\min}\) 次——這叫對手論證，是證明「只靠比較的方法不可能更快」的標準手法。

一點歷史

想法很簡單，細節卻出了名地容易寫錯。Mauchly 在 1946 年的摩爾學院講座中就提到二分搜尋，但之後發表的版本都只適用於「資料筆數比 2 的次方少 1」的情況，直到 1960 年 Lehmer 才發表任何長度都能用的版本。Bentley 說他課堂上的專業程式設計師大約十個裡有九個寫不出正確的版本；2006 年 Bloch 指出 mid = (lo + hi) / 2 這一行在包括 Java 在內的常用函式庫裡藏了好幾年：lo + hi 超過 32 位元整數的上限就會溢位。

觀察重點

  • 誰贏？找最左邊那張，再找最右邊那張。二分搜尋每次都比較快嗎？平均起來哪一種比較好？
  • 變兩倍：在 \(n = 100\)、\(200\)、\(400\)、\(800\) 各按一次「每個目標都找一次」。\(n\) 每變兩倍，兩種平均各多了多少？
  • 階梯：一邊改 \(n\)、一邊看決策樹的層數。\(n\) 在哪些值會多出一層？
  • 打亂了：在「沒排序」的卡片裡，二分搜尋還找得到哪些數？用決策樹檢查它走的路。
  • 猜數字：\(N = 100\) 時，為什麼 7 次一定夠？耍賴的電腦又為什麼總能逼你用滿 7 次？

計算方法

  • 兩種搜尋真的在畫面上的卡片上執行，每一步各比一次，和上面的描述完全一樣，沒有直接套公式。卡片是有種子的亂數：排好的相鄰相差 1 到 3、有重複的相差 0 到 2，「沒排序」是同一批數字打亂（保證不是排好的）。
  • 單元測試對 \(n = 1\) 到 1023 每一個值檢查：把每個數和每個空隙都找一遍得到的最壞情況等於 \(\lfloor \log_2 n \rfloor + 1\)；找不到時比 \(\lfloor \log_2 n \rfloor\) 或 \(\lfloor \log_2 n \rfloor + 1\) 次（\(n = 2^{k} - 1\) 時一律 \(k\) 次）；決策樹由左到右讀是排好的順序，外部與內部路徑長滿足 \(E = I + 2n\)；平均值和 Knuth 書中的封閉式相同；「找第一個」的版本回傳下界；猜數字的 \(\lceil \log_2 (N+1) \rceil\) 等於用極小化極大暴力算出的次數。
