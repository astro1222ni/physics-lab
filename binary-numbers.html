背後的原理

位值記數法

在 \(b\) 進位裡，數字只用 \(0, 1, \dots, b-1\) 來寫，而且越左邊的位數越值錢：從右邊數來第 \(k\) 位（從 \(k = 0\) 數起）要乘上 \(b^{k}\)。十進位是 \(b = 10\)；電腦用二進位（\(b = 2\)），因為開關、電晶體或磁化的小點都只有兩種穩定的狀態。二進位的每一位數叫做一個位元（bit）。

\[ (d_{k-1} \cdots d_{1} d_{0})_{b} = \sum_{i=0}^{k-1} d_{i}\, b^{i}, \qquad 0 \le d_{i} < b \]

例如 \((10100101)_2 = 2^{7} + 2^{5} + 2^{2} + 2^{0} = 128 + 32 + 4 + 1 = 165\)。

n 個位元能裝多少？

每多一個位元，組合數就加倍，所以 \(n\) 個位元有 \(2^{n}\) 種不同的組合。拿來表示從 0 開始的整數，範圍是 \(0\) 到 \(2^{n} - 1\)——燈全亮就是最大的數。要存下 \(v \ge 1\)，至少需要 \(\lfloor \log_2 v \rfloor + 1\) 個位元。

\[ 0 \le v \le 2^{n} - 1, \qquad n \ge \lfloor \log_2 v \rfloor + 1 \]

進位、借位與溢位

加一和十進位一樣：最低位加一；如果它本來就是 1，就變成 0 並進位到下一位，一路傳下去。所以「+1」會把尾端連續的 1 全變成 0、把第一個 0 變成 1。如果每一位都是 1，進位會從燈排的盡頭掉出去：結果需要 \(n + 1\) 個位元，但燈排只留得下最低的 \(n\) 位，數字就繞回 0，這叫做溢位（overflow）。乘以 2 等於所有位元往左移一格（最高位可能被推出去），除以 2 等於往右移一格——掉出去的那一位就是餘數。

八進位與十六進位：位元的速記

因為 \(8 = 2^{3}\)、\(16 = 2^{4}\)，八進位的一位剛好代表 3 個位元，十六進位的一位剛好代表 4 個位元。十六進位用 A–F 表示十到十五，所以一個位元組（8 個位元）永遠是兩位十六進位，從 00 到 FF。程式設計師常用這種寫法記長長的位元：\((1100\,1010\,1111\,1110)_2 = \text{CAFE}_{16}\)。十進位轉二進位：一直除以 2，餘數由下往上讀；要轉成 \(b\) 進位，就改成一直除以 \(b\)。

觀察重點

  • 數數的節奏：打開「自動數數」看波形圖。最低位多久翻一次？上面一位呢？為什麼每一列剛好比下面一列慢一半？
  • 長長的進位：哪些數按一次「+1」會讓很多盞燈一起改變？
  • 奇數還是偶數：只看最右邊那盞燈，它告訴你這個數的什麼？
  • 2 的次方：1、2、4、8、16……長什麼樣子？1、3、7、15、31……呢？
  • 同樣的燈，不同的名字：一位十六進位可以代替幾位二進位？為什麼八進位、十六進位很方便，十進位卻不行？

計算方法

  • 所有數字都是 0 到 \(2^{16} - 1 = 65535\) 的整數，完全精確。進位轉換用連續除以 \(b\)；+1、−1、×2、÷2 先算出結果，再只留下最低的 \(n\) 個位元——這正是固定寬度暫存器的行為。單元測試把 0 到 65535 的每個數在每種進位下都和內建的轉換比對，並檢查 +1 的進位規則、範圍頂端的溢位、除法階梯，以及「只用 +1、×2 從 0 做出一個數」的最少步數（與暴力搜尋比對）。
  • 燈泡的光暈、進位的火花和聲音只是為了好看好聽；數值本身是立刻改變的。
