CPU 排程：先到先做、最短優先與輪流

一顆 CPU，很多程式在排隊。每當 CPU 空下來，作業系統就得決定下一個輪到誰——這個決定，決定了大家要等多久。填好一張行程的工作表，看先到先做、最短優先、最短剩餘時間、輪流與優先權排程一步一步畫出甘特圖；把等待時間、周轉時間、回應時間並排比較，調整時間片，看看情境切換到底要付出多少代價。

背後的原理

下一個輪到誰？

正在執行的程式叫做行程（process）。準備好可以執行、卻還沒拿到 CPU 的行程，在就緒佇列裡排隊。每當 CPU 空出來，或有新的行程到達，作業系統的排程器就從裡面挑一個，再由分派器把 CPU 交給它。保存一個行程的狀態、載入另一個行程，叫做情境切換（context switch）；切換的那段時間，CPU 沒有做任何有用的工作。行程一旦拿到 CPU 就做到完，叫不搶先（non-preemptive）；作業系統可以中途把 CPU 收回來，叫搶先（preemptive）。

衡量「等多久」的三種時間

行程 \(i\) 的到達時間是 \(A_i\)、執行時間（需要的 CPU 時間）是 \(B_i\)、第一次開始執行的時間是 \(S_i\)、完成時間是 \(C_i\)：

\[ T_i = C_i - A_i, \qquad W_i = T_i - B_i, \qquad R_i = S_i - A_i, \qquad \overline{W} = \frac{1}{n}\sum_{i=1}^{n} W_i \]

\(T_i\) 是周轉時間（從到達到完成），\(W_i\) 是等待時間（在就緒佇列裡等的時間總和），\(R_i\) 是回應時間（到達後多久第一次拿到 CPU）。不搶先時每個行程一口氣做完，所以 \(W_i = R_i\)。把就緒佇列的長度對時間加總，剛好就是 \(\sum W_i\)：每個行程在佇列裡的每一刻都算一次。所以畫布最下面「佇列長度」那一條的面積，就等於所有人的等待時間加起來。

六種規則

  • FCFS（先到先做）：單純排隊。簡單、照順序，但只要一個很長的工作排在前面，後面每個人都得陪它等——這叫護航效應（convoy effect）。
  • SJF（最短優先，不搶先）：CPU 空下來時，挑執行時間最短的。
  • SRTF（最短剩餘時間優先）：和 SJF 一樣挑最短的，但新來的行程若比正在執行的「剩下的時間」還短，就立刻搶走 CPU。
  • RR（輪流）：一樣排隊，但每次最多只能用一個時間片 \(q\)；時間到了還沒做完，就回到隊伍最後面。
  • 優先權：優先權數字最小的先做；可以等 CPU 空下來（不搶先），也可以立刻搶（可搶先）。

為什麼「短的先做」？

如果 \(n\) 個行程同時到達，照某個順序執行、執行時間依序是 \(B_{(1)}, B_{(2)}, \ldots, B_{(n)}\)，那麼第 \(k\) 個行程會讓排在它後面的 \(n-k\) 個行程各多等 \(B_{(k)}\)：

\[ \overline{W} = \frac{(n-1)\,B_{(1)} + (n-2)\,B_{(2)} + \cdots + 1 \cdot B_{(n-1)}}{n} \]

權重最大的是第一個做的人，所以執行時間由短到長排時平均最小——這就是 SJF；由長到短排時最大。如果允許搶先，那麼不管到達時間怎麼安排，SRTF 都是最佳的：所有可能的排程中，沒有一種的平均等待時間比它更少（Schrage 1968）。代價是排程器必須事先知道執行時間；真正的作業系統只能預估，例如看這個行程前幾次用了多久。一直偏袒短的或急的，也有黑暗面——飢餓（starvation）：很長或優先權很低的行程可能一再被插隊。常見的解法是老化（aging）：等得越久，優先權慢慢提高。

時間片與切換的代價

RR 讓同時到達的 \(n\) 個行程，每一個最多等 \((n-1)\,q\) 就再輪到一次，所以回應很快。如果 \(q\) 不小於最長的執行時間，就沒有人會被打斷，RR 和 FCFS 一模一樣；如果 \(q\) 很小，每個人都被切成很多段。每次情境切換要花 \(c\) 時，CPU 有一部分時間花在切換、而不是做事（\(C_{\max}\) 是最後一個行程完成的時間）：

\[ \text{CPU 使用率} = \frac{\sum B_i}{C_{\max}}, \qquad \text{切換占的比例} = \frac{(\text{切換次數}) \times c}{C_{\max}} \]

觀察重點

  • 護航效應：選範例「課本：24、3、3 同時到達」，比較 FCFS 和 SJF。FCFS 的等待時間，有多少是那一個長工作造成的？
  • 掃過時間片：在時間片圖上，RR 的折線從哪個 \(q\) 開始和 FCFS 重合？最好的 \(q\) 是最小的那個嗎？
  • 回應快、完成慢：比較 RR 和其他方法的平均回應時間與平均周轉時間。輪流換到了什麼？又付出了什麼？
  • 切換的價錢：把情境切換成本調成 1、時間片調成 1，CPU 使用率變成多少？
  • 佇列的面積：播到一半暫停，把到目前為止的等待時間加起來，為什麼一定和佇列長度那一條的陰影面積一樣？
  • 有人贏得了 SRTF 嗎？隨機產生一張工作表，試遍每一種方法和每一個時間片。SRTF 需要事先知道什麼，別人不用？

計算方法

  • 事件驅動模擬。時間從一個事件跳到下一個事件：有行程到達、執行完畢、時間片用完、或情境切換結束。所有時間都是整數或 0.5 的倍數，所以每個結果都是精確值。每個行程只有一段 CPU 工作，沒有 I/O。
  • 平手規則。執行時間、剩餘時間或優先權相同時，先比到達時間，再比編號。新來的行程要「嚴格」比較好才會搶先，一樣好就不白白切換。時間片用完的那一刻剛好做完，算做完。時間片用完時如果沒有別人在等，它就繼續做（畫面上的 ¦ 記號），不算切換。
  • RR 的同一時刻。某個行程用完時間片的那一刻，剛好有新行程到達，兩個都要進佇列。各本教科書沒有統一說誰先；本頁預設讓新到達的先排——這樣算正好重現 Stallings 課本五個行程 A–E 的例子（RR、\(q = 1\) 時完成時間是 4、18、17、20、15）。勾選設定裡的方框，就改成讓剛被換下的先排，看看你的工作表結果會不會變。
  • 情境切換。CPU 從一個行程直接換到另一個行程時，先花掉切換成本，切換結束的那一刻排程器才挑下一個（所以切換期間到達的行程也有機會被挑中）。CPU 閒置之後開始執行不用花切換時間。等切換的時間也算在等待時間裡。
  • 單元測試檢查：Silberschatz 等人課本的例子（平均等待時間 17、3、7、6.5、17/3、8.2），Stallings 課本例子在 FCFS、SJF、SRTF、RR（\(q = 1\)、\(q = 4\)）下五個行程的完成時間；每個行程的執行時間總和都不變、甘特圖不重疊、有人在等時 CPU 不會閒置（隨機 24 000 個排程）；就緒佇列的面積等於等待時間的總和；所有人同時到達時，SJF 是 \(n!\) 種順序裡最好的（\(n \le 6\)）；SRTF 和用動態規劃窮舉所有排程得到的最佳值相同；時間片不小於最長的執行時間時 RR 和 FCFS 完全相同；以及 RR 同一時刻的兩種排隊規則。
