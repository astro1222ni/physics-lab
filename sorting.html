背後的原理

排序，以及怎麼數「做了多少事」

排序就是把一串資料由小到大排好。要比較兩個演算法誰快，用秒數量不太公平——會受電腦和程式語言影響。我們改數基本操作做了幾次：兩個資料值比較了幾次（比較次數 \(C\)）、兩個位置交換了幾次（交換次數 \(S\)），以及合併排序把值寫回陣列幾次（寫入次數 \(W\)）。這就是課綱說的「指令執行次數」。最重要的是次數隨資料長度 \(n\) 怎麼成長：像 \(n^{2}\)，還是像 \(n\log_2 n\)。

五種排序

  • 泡沫排序：從左到右比較相鄰的兩個，左邊比較大就交換；一輪下來，最大的值會「浮」到最右邊。這個版本只要有一整輪都沒有交換，就提早結束。
  • 選擇排序：每一輪從還沒排好的部分找出最小值，和那一輪的第一格交換（最小值本來就在那裡就不換）。
  • 插入排序：像整理手上的撲克牌：左邊是已經排好的部分，把下一張一格一格往左交換，直到左邊那張不比它大。
  • 合併排序（由上而下）：把資料切成兩半（左半 \(\lceil n/2 \rceil\) 個、右半 \(\lfloor n/2 \rfloor\) 個），各自排好，再把兩疊合併：比較兩疊最前面的值，把小的寫回陣列。合併時要先把資料複製到暫存區，所以需要額外的記憶空間。
  • 快速排序（Lomuto 分割）：取區段最後一個值當樞紐，把不比樞紐大的值依序換到前面，再把樞紐換到它們後面——樞紐就在最後的位置上了；接著用同樣的方法排左右兩段。三數取中則先比較第一個、中間、最後一個，取三者的中位數當樞紐。

要比較幾次？

泡沫、插入與快速排序（取最後一個當樞紐）最多要比較 \(\frac{n(n-1)}{2}\) 次；選擇排序則不管資料長怎樣，都剛好比這麼多次：

\[ (n-1) + (n-2) + \cdots + 2 + 1 = \frac{n(n-1)}{2} \]

對已經排好的資料，泡沫排序與插入排序都只要 \(n - 1\) 次；快速排序（取最後一個當樞紐）卻剛好碰上最壞的 \(\frac{n(n-1)}{2}\) 次，因為每次樞紐都是區段裡最大的值，分割一次只少掉一個。

把總共 \(m\) 個值的兩疊合併，最多比較 \(m - 1\) 次，所以合併排序最壞的比較次數 \(W(n)\) 滿足 \(W(n) = W(\lceil n/2\rceil) + W(\lfloor n/2\rfloor) + n - 1\)、\(W(1) = 0\)，解出來是

\[ W(n) = n\lceil \log_2 n \rceil - 2^{\lceil \log_2 n \rceil} + 1 \]

例如 \(n = 64\) 時是 321 次，遠少於 \(\frac{n(n-1)}{2} = 2016\) 次。寫入次數則和資料無關：每一層合併都把所有值寫回一次，\(n\) 是 2 的冪時剛好 \(n\log_2 n\) 次。

逆序數

位置 \(i < j\) 而 \(a_i > a_j\) 的一對，叫做一個逆序。泡沫排序和插入排序都只交換相鄰的兩個，而且只在左邊比較大時才交換，每換一次剛好消掉一個逆序，所以兩者的交換次數都等於資料的逆序數。把 \(n\) 個不同的值所有可能的排列平均起來，逆序數是 \(\frac{n(n-1)}{4}\)——最大值的一半。

穩定性

如果相同的值排完之後仍保持原本的先後順序，這個排序就是穩定的。打開「標出相同值的原本順序」，相同的值會標上 A、B、C……並由淺到深上色。泡沫、插入、合併排序只在後面的值嚴格比較小時，才讓它越過前面的值，所以穩定；選擇排序與快速排序會做長距離的交換，可能把一個值帶著跳過和它相同的值，所以不穩定。「不穩定」不是「一定會打亂」，而是「不保證不打亂」。

比較排序的極限

任何只靠「一次比較兩個值」來排序的方法，最壞情況至少要比較 \(\lceil \log_2 n! \rceil\) 次：\(n\) 個不同的值有 \(n!\) 種排列，每次比較只有兩種結果，\(k\) 次比較最多只能分辨 \(2^{k}\) 種情況。\(n = 64\) 時這個下限是 296 次——合併排序的 321 次已經很接近了。

觀察重點

  • 已經排好：泡沫和插入排序幾乎一下就結束，快速排序（不用三數取中）卻最慢。為什麼？
  • 選擇排序不看資料：它在各種資料上的比較次數都一樣。交換次數呢？反序的資料它換了幾次？
  • 幾乎排好：讓五種一起比。誰最先跑完？領先多少？
  • 很多重複：哪幾種把相同值的 A、B、C 順序打亂了？這時三數取中讓快速排序變快還是變慢？
  • 看圖：用反序的資料、不同的 \(n\) 跑幾次泡沫排序，點排成什麼形狀？合併排序呢？
  • 一個小定理：同一份資料，插入排序的比較次數會不會比泡沫排序多？（不會——試著想想為什麼。）

計算方法

  • 開始播放之前，頁面已經用 JavaScript 把選好的排序實際跑一遍，把每一次比較、交換、寫入記成步驟清單；畫面再照著清單一步一步播放（「上一步」是從頭重播到前一步）。所有計數都是實際數出來的，不是用公式算的。
  • 計數的定義：比較只算兩個資料值之間的比較（迴圈變數的比較不算）；交換只算真的交換了兩個不同位置；寫入是合併排序把值寫回陣列（複製到暫存區不算）。遞迴深度是同時進行中、而且區段至少還有 2 個值的呼叫層數。「五種一起比」每一步讓每種演算法各做一個基本操作（一次比較、交換或寫入），所以先跑完的，就是基本操作總數最少的。
  • 亂序、幾乎排好、很多重複用有種子的虛擬亂數（mulberry32）產生。幾乎排好是把排好的資料做大約 n/8 次隨機的相鄰交換；很多重複只用 1–4 四種值。自訂資料只在你的瀏覽器裡處理，最多 64 個。
  • 單元測試檢查：五種排序在 7 個以內所有排列、以及有重複值的小資料上都排對；泡沫與插入排序每個逆序剛好交換一次；選擇排序的比較次數固定是 n(n − 1)/2、交換次數是 n 減去排列的循環數；把 8 個以內的所有排列都試過，確認合併排序的最壞次數等於上面的公式、快速排序的最少次數等於 C(n) = n − 1 + C(⌊(n − 1)/2⌋) + C(⌈(n − 1)/2⌉)；哪些排序穩定；以及一步步重播和直接排序的結果相同。
