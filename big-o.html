時間複雜度：成長速度的比較

五個小演算法真的在同一批 \(n\) 個數上執行，頁面數出每一種做了幾次基本操作：二分搜尋、循序搜尋、合併排序、用雙層迴圈兩兩比較、列出所有子集合。讓它們和 \(\log_2 n\)、\(n\)、\(n\log_2 n\)、\(n^2\)、\(2^n\) 這幾條曲線一起賽跑，把 \(n\) 加倍看次數怎麼長大，再看看很大的常數因子什麼時候就不重要了。

試試看：按「開始賽跑」，看誰先跑完；再按幾次「n 加倍」，比一比每一種的次數變成幾倍。

背後的原理

數操作的次數，不數秒數

程式跑多久，和電腦、程式語言甚至室溫都有關；數「基本操作執行了幾次」只和演算法與輸入有關，所以拿來比較演算法才公平。這一頁每個演算法都只數一種操作：

  • 二分搜尋：把目標和 \(a[mid]\) 比大小算一次，\(mid = \lfloor (lo + hi)/2 \rfloor\)。找一個比全部都大的數要比 \(\lfloor \log_2 n \rfloor + 1\) 次，這是它最多可能的次數。
  • 循序搜尋：把目標和一個元素比是否相等算一次；找不到要比 \(n\) 次。
  • 合併排序（由上而下，左半 \(\lceil m/2 \rceil\) 個）：合併時比較兩個元素的大小算一次。合併 \(m\) 個元素最多比 \(m - 1\) 次，所以最壞情況 \(W(n)\) 滿足 \(W(n) = W(\lceil n/2 \rceil) + W(\lfloor n/2 \rfloor) + n - 1\)，解出來是 \(W(n) = n\lceil \log_2 n \rceil - 2^{\lceil \log_2 n \rceil} + 1\)。已排好的資料比較少，因為左半總是先用完。
  • 兩兩比較（雙層迴圈跑過所有 \(i < j\)，例如找重複的值）：比較 \(a[i]\) 與 \(a[j]\) 算一次，共 \((n-1) + (n-2) + \dots + 1 = n(n-1)/2\) 次。
  • 列出所有子集合（例如找總和剛好等於某數的一組數）：檢查一個子集合算一次。每個元素只有「選」或「不選」，所以共有 \(2^n\) 個子集合（包含空集合）。

成長速度與漸近記號

\(n\) 很大的時候，重要的是次數的「樣子」，不是確切的值。照 Cormen 等人的課本第 3 章，對最後都不是負數的函數：

\[ f(n) = O(g(n)) \iff \exists\, c > 0,\ n_0 :\ 0 \le f(n) \le c\, g(n) \ \text{for all}\ n \ge n_0 \]
\[ f(n) = \Omega(g(n)) \iff \exists\, c > 0,\ n_0 :\ 0 \le c\, g(n) \le f(n) \ \text{for all}\ n \ge n_0 \]
\[ f(n) = \Theta(g(n)) \iff \exists\, c_1, c_2 > 0,\ n_0 :\ c_1 g(n) \le f(n) \le c_2\, g(n) \ \text{for all}\ n \ge n_0 \]

所以 \(O\) 是上界、\(\Omega\) 是下界、\(\Theta\) 是兩者同時成立：\(n(n-1)/2 = \Theta(n^2)\)（取 \(c_1 = 1/4\)、\(c_2 = 1/2\)、\(n_0 = 2\)）、\(\lfloor \log_2 n \rfloor + 1 = \Theta(\log n)\)，合併排序不管哪一種資料都是 \(\Theta(n \log n)\) 次比較。Knuth 在 1976 年的短文〈Big Omicron and Big Omega and Big Theta〉提議就這樣使用 \(\Omega\) 與 \(\Theta\)，好讓大家不再拿 \(O\) 來表示下界。式子裡的「=」其實是「屬於這個集合」的意思。

「常數因子」卡片就是 \(O\) 的定義：如果從交叉點 \(n_0\) 起都有 \(a\,f(n) \le b\,g(n)\)，那裡就有 \(f(n) \le (b/a)\, g(n)\)，所以 \(c = b/a\) 和這個 \(n_0\) 就證明了 \(f(n) = O(g(n))\)。常數可以把交叉點推遠，卻擋不住長得快的那一邊最後勝出。

加倍實驗

把 \(n\) 加倍，是從量到的次數認出成長速度最快的方法：

\[ \frac{T(2n)}{T(n)}:\quad \log_2(2n) = \log_2 n + 1,\quad \frac{2n}{n} = 2,\quad \frac{2n\log_2 2n}{n \log_2 n} = 2\Big(1 + \frac{1}{\log_2 n}\Big),\quad \frac{(2n)^2}{n^2} = 4,\quad \frac{2^{2n}}{2^n} = 2^n . \]

對數只多一步、線性變兩倍、\(n\log n\) 比兩倍多一點、平方變四倍——指數則是變成原來的平方。

對數軸上的直線

縱軸取對數時，\(\log 2^n = n \log 2\) 是 \(n\) 的一次式：指數成長在半對數紙上是直線。兩個軸都取對數時，\(\log n^k = k \log n\) 是斜率 \(k\) 的直線：\(n\) 的每一種次方都變成直線，斜率就是次方——\(n^2\) 的坡度是 \(n\) 的兩倍。

每個操作 1 奈秒

假設每一次計數的操作花 \(1\ \text{ns} = 10^{-9}\ \text{s}\)。\(n = 1000\) 時兩兩比較只要半毫秒，可是只有 \(n = 60\) 個元素的所有子集合就要 \(2^{60}\ \text{ns} \approx 1.15 \times 10^{9}\ \text{s} \approx 36.5\) 年（1 年 = 365.25 天）。電腦快 1000 倍，\(n^2\) 的演算法能處理的量大約變成 31 倍，\(2^n\) 的卻只能多處理大約 10 個，因為 \(2^{10} \approx 1000\)。

觀察重點

  • 賽跑：\(n = 12\) 時誰先跑完？誰好像永遠跑不完？把 \(n\) 調得很小，名次還一樣嗎？
  • 加倍：多按幾次「n 加倍」。哪一種只多一次？哪一種變成平方？兩兩比較的倍數會越來越接近 4 嗎？
  • 常數：比較 \(100n\) 和 \(n^2\)。\(n = 10\) 時誰比較大？\(n = 1000\) 呢？有沒有哪一個常數能讓 \(n^2\) 永遠比較小？
  • 直線：哪一種座標軸讓 \(2^n\) 變直線？哪一種讓 \(n\) 和 \(n^2\) 變直線？斜率告訴你什麼？
  • 同一個等級、不同的次數：同一個 \(n\) 下比較合併排序的「隨機」「已排好」「最壞情況」。次數不一樣，卻都是 \(\Theta(n \log n)\)——為什麼？

計算方法

  • 畫面上的次數都是真的把演算法在資料上執行、每做一次計數的操作就加一得到的；只有 \(n > 20\) 的列出所有子集合改用公式 \(2^n\)（超過兩百萬個子集合會讓頁面卡住），並標明「用公式算」。賽跑時所有跑道共用一個時鐘、每一拍各做一次操作，所以每條跑道畫的都是演算法做了這麼多次操作後真正的狀態。
  • 交叉點的算法：\(n \le 4096\) 逐一檢查，更大的地方兩邊比值的對數是單調的，用二分法找。「剛好相等」用精確的整數運算（BigInt）確認，並利用「只有 \(n\) 是 2 的次方時 \(\log_2 n\) 才是有理數」。
  • 單元測試檢查：循序搜尋 \(n\) 次、二分搜尋 \(\lfloor \log_2 n \rfloor + 1\) 次（\(n = 1\) 到 300 每個目標與每個空隙裡的最大值）；雙層迴圈 \(n(n-1)/2\) 次；合併排序一定排好、從不超過 \(n\lceil \log_2 n \rceil - 2^{\lceil \log_2 n \rceil} + 1\)、在「最壞情況」的資料剛好達到、在 \(n = 2^k\) 的已排好資料是 \(nk/2\)（\(n\) 到 1000 全部）；子集合 \(2^n\) 個；加倍的倍數；\(2^{60}\) 奈秒約 36.5 年；交叉點和逐一檢查的結果相同。
